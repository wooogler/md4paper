# md4paper

*[English](README.en.md) · 한국어*

논문 PDF를 **(1) 헤더 구조가 제대로 정렬된 마크다운**과 **(2) 한국어 번역 마크다운**으로 바꿔주는
로컬 도구입니다. 브라우저에서 쓰는 웹 UI가 기본이고(서버는 내 컴퓨터에서만 돕니다), 자동화를 위한
CLI도 함께 들어 있습니다.

![변환 화면 — 왼쪽 섹션 트리, 오른쪽 마크다운 프리뷰](docs/images/02-convert.png)

- PDF → 마크다운 추출은 [Docling](https://github.com/docling-project/docling)(MIT)으로 **내 컴퓨터에서** 수행합니다.
- 섹션 트리에서 헤더 레벨을 직접 교정하고, PDF 원본과 나란히 대조하며 확인합니다.
- 참고문헌 파싱·인용 링크·용어집·한국어 번역은 **LLM API**를 사용합니다(선택 기능, 키 필요).

## 무엇이 다른가 — 사람이 끼어들 수 있습니다

PDF를 통째로 LLM에 던지고 "번역해줘" 하는 방식과의 차이는, **자동 결과를 사람이 고칠 자리가
파이프라인 중간중간에 열려 있다**는 점입니다.

- **섹션 구조를 직접 고칩니다.** 자동 감지된 헤더 레벨이 틀리면 트리에서 바꾸고, 같은 번호 체계의
  헤더는 한 번에 조정합니다. 필요 없는 섹션은 빼고, 놓친 헤더는 넣습니다. 프리뷰에 즉시 반영됩니다.
- **고친 판단을 기억합니다.** "Acknowledgments는 h2" 같은 교정은 헤더 이름별로 저장돼, 같은 학회
  포맷의 다음 논문에 자동으로 적용됩니다.
- **용어집을 먼저 확정하고 번역합니다.** LLM이 뽑은 용어 후보를 표에서 고친 뒤 그 용어집으로
  번역하므로, 문서 전체에서 번역어가 흔들리지 않습니다.
- **번역 방식을 고릅니다.** 문체(해라체/합니다체/해요체), 헤더를 영어로 둘지, 어느 섹션까지
  번역할지를 섹션 단위로 선택합니다.
- **원본과 대조하며 검수합니다.** 섹션 제목을 누르면 그 PDF 페이지로 이동하고, EN | KO 나란히 보기로
  번역을 확인하고, 마크다운을 직접 손볼 수 있습니다.
- **정해진 규칙은 LLM에 맡기지 않습니다.** 번호 기반 헤더 재정렬, 그림·표 캡션 짝짓기, 이미지 이름
  정리, 수식·코드·링크 보호, 러닝 헤더·저작권 문구·**투고 원고 여백의 줄 번호** 제거는 코드가
  결정론적으로 처리합니다. LLM은 번역·용어집·참고문헌 파싱에만
  씁니다 — 그래서 결과가 재현되고 비용도 예측 가능합니다.

## ⚠️ 먼저 읽어주세요 — 이 프로젝트는 "바이브 코딩"으로 만들었습니다

이 저장소의 코드는 **대부분 LLM(Claude Code)이 작성**했고, 사람이 한 줄씩 검토하지 않았습니다.
개인 연구용으로 만든 도구를 그대로 공개한 것이며, 다음을 이해하고 사용해 주세요.

- **AS-IS, 무보증.** 언제든 깨질 수 있고, 조용히 틀린 결과를 낼 수 있습니다. 프로덕션·업무 크리티컬한
  파이프라인에 넣지 마세요.
- **추출이 내용을 빠뜨릴 수 있습니다.** 표·수식·2단 조판·각주는 특히 취약합니다. 결과물을 반드시
  **원본 PDF와 대조**하세요(웹 UI에 나란히 보기 기능이 있습니다).
- **번역은 LLM이 합니다 — 오역·누락·환각이 있을 수 있습니다.** 숫자, 수식, 실험 결과, 인용 번호가
  바뀌어도 도구는 눈치채지 못할 수 있습니다. 인용하거나 배포할 글에 쓰기 전에 사람이 확인해야 합니다.
- **내 논문 본문이 외부 LLM API로 전송됩니다.** 번역·용어집·참고문헌 파싱을 실행하면 해당 텍스트가
  OpenAI/Anthropic/Google 서버로 갑니다. **미공개 원고, 대외비 문서, 저작권이 걸린 자료**에는
  사용하지 마세요. 추출(PDF→마크다운)만 쓰면 네트워크로 나가는 텍스트는 없습니다.
- **API 요금이 실제로 청구됩니다.** 논문 한 편에 보통 $0.03-0.14 수준이며(→ [비용](#비용--논문-한-편에-얼마나-드나)),
  비용은 전적으로 사용자 부담입니다. 추출만 쓰면 요금은 들지 않습니다.
- **API 키는 평문으로 저장됩니다** (`~/.config/md4paper/config.toml`, POSIX에서는 권한 0600).
  공용 컴퓨터에서는 파일 저장 대신 환경 변수를 쓰세요.
- **버그 리포트는 환영하지만, 지원을 약속하지 않습니다.** 이슈/PR은 여유 있을 때만 봅니다.

## 요구 사항

| 항목 | 내용 |
|---|---|
| OS | Windows 10/11, macOS(Apple Silicon·Intel), Linux |
| Python | 3.11 이상 — **직접 설치 안 해도 됩니다**(uv가 알아서 받아옵니다) |
| 디스크 | 의존성 약 **1.3GB**(macOS 실측) + 첫 변환 시 Docling 모델 약 **1.1GB** 다운로드 (Linux는 CUDA용 torch 때문에 더 커질 수 있음) |
| 메모리 | 4GB 이상 권장 (GPU 필수 아님, CPU로 동작) |
| 네트워크 | 설치·첫 모델 다운로드에 필요. 이후 추출은 오프라인 가능 |
| LLM 키 | 번역/인용/용어집에만 필요(선택). OpenAI · Anthropic · Google Gemini 중 하나 |
| 앱 창 | 선택 — 아이콘으로 여는 독립 창(pywebview). macOS·Windows는 OS 웹뷰를 그대로 쓰고, Linux는 WebKit2GTK가 필요합니다(없으면 브라우저로 열립니다) |

## 설치

### 한 줄 설치 — 아이콘까지 한 번에 (권장)

터미널에 이 줄을 붙여넣으면 uv·파이썬·md4paper·앱 아이콘까지 한 번에 끝납니다.

**macOS / Linux**:
```bash
curl -LsSf https://raw.githubusercontent.com/wooogler/md4paper/main/install.sh | sh
```

**Windows** (PowerShell):
```powershell
irm https://raw.githubusercontent.com/wooogler/md4paper/main/install.ps1 | iex
```

끝나면 Launchpad·시작 메뉴에 **md4paper 아이콘**이 생깁니다. 눌러서 여세요
(→ [앱으로 열기](#앱으로-열기--아이콘-등록-선택)). 같은 줄을 다시 실행하면 최신 버전으로 업데이트됩니다.

- **무엇을 하나** — uv(파이썬까지 관리하는 패키지 관리자)가 없으면 설치하고, `uv tool install`로
  md4paper를 넣고, `md4paper app`으로 아이콘을 등록합니다. 스크립트는 [install.sh](install.sh) ·
  [install.ps1](install.ps1)에 그대로 있으니 실행 전에 읽어 보세요(모르는 스크립트를 파이프로
  실행하는 건 원래 조심할 일입니다).
- 의존성 약 1.3GB를 받으므로 처음에는 몇 분 걸립니다.
- **설치 파일(.dmg·.exe)이 아니라 스크립트인 이유** — 앱을 **사용자 컴퓨터에서 조립**하기 때문에
  코드 서명·공증이 필요 없고, macOS의 "확인되지 않은 개발자" 경고나 Windows SmartScreen 경고도
  뜨지 않습니다. 1.5GB짜리 설치 파일을 내려받을 일도 없습니다.
- 제거: `md4paper app --remove && uv tool uninstall md4paper`

### 직접 설치 — uv를 이미 쓰거나, 코드를 고칠 사람

패키지 관리자 [uv](https://docs.astral.sh/uv/)만 설치하면 Python까지 uv가 처리합니다.

#### 1단계 — uv 설치

**Windows** (PowerShell):
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```
설치 후 **PowerShell 창을 닫고 새로 열어야** `uv` 명령이 잡힙니다.

**macOS / Linux**:
```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```
(macOS는 Homebrew도 됩니다: `brew install uv`)

확인: `uv --version`

#### 2단계 — md4paper 설치하고 웹 UI 켜기

##### 방법 A: 클론해서 쓰기 (개발용 권장)

**Windows** (PowerShell):
```powershell
git clone https://github.com/wooogler/md4paper.git
cd md4paper
uv sync --extra ui
uv run md4paper ui
```

**macOS / Linux**:
```bash
git clone https://github.com/wooogler/md4paper.git
cd md4paper
uv sync --extra ui
uv run md4paper ui
```

`--extra ui`가 웹 UI(NiceGUI)를 포함합니다. 의존성 내려받는 데 처음 몇 분 걸립니다.
설치가 잘 됐는지 보려면 `uv run md4paper doctor`.

##### 방법 B: 클론 없이 바로 실행

**Windows** (PowerShell):
```powershell
uvx --from "md4paper[ui] @ git+https://github.com/wooogler/md4paper" md4paper ui
```

**macOS / Linux**:
```bash
uvx --from 'md4paper[ui] @ git+https://github.com/wooogler/md4paper' md4paper ui
```

첫 실행은 의존성을 받으므로 몇 분 걸립니다. 이 방식에서 작업 폴더 기본값은 `~/md4paper/output`
(Windows는 `C:\Users\<사용자>\md4paper\output`)입니다.

## 앱으로 열기 — 아이콘 등록 (선택)

[한 줄 설치](#한-줄-설치--아이콘까지-한-번에-권장)를 했다면 아이콘이 **이미 등록돼 있습니다**.
클론해서 쓰고 있다면 저장소에서 두 줄을 실행하세요:

```bash
uv sync --extra ui --extra native   # 앱 창 의존성(pywebview) 추가
uv run md4paper app                 # 아이콘 등록
```

| OS | 만들어지는 것 | 어디서 열리나 |
|---|---|---|
| macOS | `~/Applications/md4paper.app` | Launchpad · Spotlight · Finder · Dock |
| Windows | 시작 메뉴의 `md4paper` (`--desktop`을 주면 바탕화면에도) | 시작 메뉴 |
| Linux | `~/.local/share/applications/md4paper.desktop` | 앱 메뉴 |

아이콘을 누르면 브라우저 탭이 아니라 **독립 앱 창**이 뜹니다 — 화면과 기능은 웹 UI와 똑같습니다.
서버는 여전히 127.0.0.1에만 붙고, 창을 닫으면 서버도 함께 내려갑니다. 터미널에서 같은 창을 띄우려면
`uv run md4paper ui --native`입니다(브라우저로 열고 싶으면 그냥 `md4paper ui`).

- **zip 내려받기**는 앱 창에서도 됩니다 — 브라우저 다운로드 대신 **OS 저장 대화상자**가 떠서 위치를
  고릅니다.
- **환경변수는 상속되지 않습니다.** 아이콘으로 띄우면 셸에서 `export` 한 `OPENAI_API_KEY` 같은 값이
  보이지 않습니다. 홈 화면 왼쪽 **AI 설정**에 키를 저장해 두세요(`~/.config/md4paper/config.toml`).
- **아무 일도 일어나지 않으면** 로그를 보세요 — macOS는 `~/Library/Logs/md4paper.log`. 실행에
  실패하면 앱이 알림창으로 알려 줍니다.
- **저장소를 옮기거나 가상환경을 다시 만들었다면** `md4paper app`을 다시 실행하세요.
  런처에 인터프리터 경로가 박혀 있습니다. (한 줄 설치로 넣었다면 업데이트해도 경로가 그대로라
  다시 할 필요가 없습니다.)
- **앱 창을 못 띄우는 환경**(리눅스에 WebKit2GTK·Qt가 없는 경우 등)에서는 아이콘이 먹통이 되는 대신
  **브라우저로 엽니다**. 이유는 실행 로그에 적힙니다.
- 제거: `md4paper app --remove`

> `uv sync --extra X`는 지정하지 않은 extra를 제거합니다. 앱 창을 쓰려면 **항상 두 개를 같이**
> 주세요: `uv sync --extra ui --extra native`.

## 웹 UI 사용법

`md4paper ui`를 실행하면 터미널에 `http://127.0.0.1:8080` 주소가 찍히고 브라우저가 열립니다.
(브라우저 대신 앱 창으로 쓰고 싶으면 → [앱으로 열기](#앱으로-열기--아이콘-등록-선택))
**서버는 127.0.0.1(내 컴퓨터)에만 바인딩되므로 외부에서 접속할 수 없습니다.** 포트가 사용 중이면
빈 포트를 자동으로 골라 실제 주소를 출력합니다. (`--port 9000`으로 지정, `--no-show`로 브라우저
자동 열기 끄기, `md4paper ui <이름>.md4/`로 기존 작업 바로 열기)

### 1. 홈 — 올리고, 다시 찾기

![홈 화면 — PDF 드롭존과 변환한 논문 목록](docs/images/01-home.png)

PDF를 끌어다 놓으면 바로 변환이 시작됩니다. 여러 개를 올리면 순서대로(배치) 처리합니다.
이미 마크다운인 `.md` 파일도 받습니다(추출을 건너뛰고 구조 정리부터).

- 오른쪽 **변환한 논문** 목록에서 제목·저자·venue로 검색하고, 카드를 눌러 언제든 이어서 작업합니다.
- 목록 위 선택 상자로 **한 프로젝트만 걸러 보거나** 프로젝트별 구역으로 묶어 봅니다. 카드의
  **프로젝트 칩**을 눌러 다른 묶음으로 옮기면 저장 위치의 사본(마크다운·이미지·PDF·bib 항목)도
  함께 따라갑니다.
- 카드의 **📌 고정**을 누르면 그 논문이 목록 맨 위 **'고정한 논문'** 구역으로 올라갑니다(왼쪽에 파란
  선이 붙습니다). 정렬을 최근순/제목순으로 바꿔도 고정한 논문의 자리는 움직이지 않고, **최근 20편
  밖으로 밀려나도 목록에 남습니다.** 같은 논문이 리뷰 화면 헤더의 **논문 탭**으로도 나옵니다
  (→ [논문 여러 편을 한꺼번에](#논문-여러-편을-한꺼번에--헤더-탭과-새-창)). 📌를 다시 누르면 풀립니다.
- 카드의 **⧉**는 그 논문을 **새 창**으로 엽니다 — 두 논문을 나란히 놓고 볼 때.
- 왼쪽 **AI 설정**에 API 키를 붙여넣고 "연결 테스트"로 즉시 확인할 수 있습니다(번역·인용에만 필요).
- 왼쪽 **기본 변환·번역 설정**은 앞으로 올릴 논문에 적용될 기본값입니다.
- 왼쪽 **프로젝트**에서 논문 묶음을 만들고 묶음마다 폴더를 정합니다 — 아래
  [프로젝트](#프로젝트--논문을-묶어-관리하기) 참조.
- 왼쪽 **저장 위치**에서 변환한 논문이 쌓일 폴더를 정합니다 — 아래 [저장 위치](#저장-위치--변환한-논문을-한-폴더에-쌓기) 참조.
- 목록에서 여러 편을 체크해 한 zip으로 **내보내기**할 수 있습니다.
- 카드 오른쪽 휴지통은 **목록에서 숨기기**(파일은 그대로 두고 목록에서만 감춤)와 **파일 삭제**(작업
  디렉토리까지 영구 삭제) 중에서 고릅니다. 숨긴 논문은 목록 위의 **숨긴 논문 N편 보기**로 언제든 되돌립니다.
  파일 삭제는 원본 PDF·추출 캐시·이미지가 든 논문 폴더를 통째로 지우고, 저장 위치에 쌓아 둔 사본까지
  함께 정리합니다 — 공통 폴더든 프로젝트 폴더든 마크다운·이미지·PDF와 **`references.bib`의 그 논문
  항목**을 같이 걷어냅니다(다이얼로그의 체크박스를 끄면 사본은 남깁니다 — 지워질 폴더 경로를 그 자리에
  보여줍니다).

### 논문 여러 편을 한꺼번에 — 헤더 탭과 새 창

한 편만 붙들고 있는 경우는 드뭅니다. 관련 논문을 오가며 읽으려면 두 가지 길이 있습니다.

- **헤더 탭** — 리뷰 화면 맨 위에 **고정한 논문이 탭으로** 놓입니다. 지금 보고 있는 논문은 흰 탭이고
  (본문과 맞닿아 이어집니다), 다른 탭을 누르면 홈을 거치지 않고 그 논문으로 바로 넘어갑니다.
  탭에 마우스를 올리면 나오는 ×는 **고정 해제**이고(논문·파일은 그대로), 탭 줄 끝의 **📌**로 지금
  논문을 그 자리에서 고정하거나 풉니다. 고정한 논문이 많으면 탭 줄이 가로로 스크롤합니다.
- 헤더는 **한 줄(44px)**입니다. 단계(1·변환 / 2·번역 / 3·뷰어)도 오른쪽 끝에 같은 방식으로 물린
  탭인데, 논문 탭보다 한 급 작고(26px) 활성 글자가 파랑입니다 — **왼쪽 탭 = 어느 논문, 오른쪽 탭 =
  그 논문의 어느 화면**으로 층이 갈립니다. 아이콘 2단 탭이 먹던 높이(44px)만큼 본문이 넓어졌습니다.
- **새 창** — 탭 옆의 **⧉**는 같은 논문을 **창 하나에 하나씩** 띄웁니다. 앱 창으로 쓰고 있으면 앱
  창이 하나 더 열리고(같은 서버를 봅니다 — 한쪽에서 고친 게 다른 쪽에도 그대로 반영됩니다),
  브라우저로 쓰고 있으면 새 탭이 열립니다. 논문 둘을 진짜로 **나란히** 놓고 비교할 때 쓰세요.
  본 창을 닫으면 서버가 내려가면서 딸린 창들도 함께 닫힙니다.
  - **같은 논문은 두 창에 열지 않습니다.** 하이라이트·메모는 창마다 파일 전체를 다시 쓰기 때문에
    한 논문을 두 창에서 고치면 나중에 저장한 쪽이 앞을 덮습니다. 이미 떠 있으면 그렇다고 알려 줍니다.
  - **창이 여러 개인 동안 zip 저장은 위치를 묻지 않습니다** — 다운로드 폴더에 떨어뜨리고 그 자리를
    열어 줍니다. 앱 창의 저장 대화상자는 '어느 창에 붙는지'가 정해져 있어서, 형제 창에서 누른 저장이
    본 창에 시트로 떠 '아무 일도 안 일어난 것처럼' 보이는 편이 더 나쁘기 때문입니다.

### 읽던 자리로 돌아옵니다 — 단계와 스크롤 기억

- 헤더 탭으로 논문을 옮겼다 돌아오면 **그 논문에서 마지막으로 보던 단계**(변환/번역/뷰어)로 열립니다.
  처음 여는 논문만 기존 규칙대로 열립니다(번역이 있으면 뷰어, 없으면 변환).
- **스크롤 위치도 되돌립니다.** 논문·단계·패널별로 따로 기억하므로 뷰어의 원문·번역 컬럼, 목차, PDF,
  변환 탭의 마크다운이 각자 제 자리로 돌아옵니다. 홈의 논문 목록도 스크롤한 자리로 돌아옵니다.
- 기억은 **창(세션) 안에서만** 삽니다 — 창을 나란히 띄워도 서로 섞이지 않고, 앱을 닫으면 잊습니다.
  복원한 뒤 바로 직접 스크롤하면 사용자가 고른 자리가 이깁니다.

### 어느 화면에서든 Cmd/Ctrl+F로 찾기

앱 창에는 브라우저의 찾기 바가 없어서 Cmd+F를 눌러도 아무 일이 일어나지 않았습니다. 이제
**앱 창에서도 브라우저에서도 같은 찾기 바**가 뜹니다 — 오른쪽 위에 붙고, 전체 결과 수(`3 / 26`)를
세어 노란색으로 모두 표시하고 현재 결과만 주황색으로 짚어 줍니다.

- **Enter**(다음) · **Shift+Enter**(이전) · **Esc**(닫기), macOS의 **Cmd+G / Cmd+Shift+G**도 됩니다.
- 마크다운 프리뷰, 뷰어의 원문·번역 컬럼, 섹션 트리, 목차 — **지금 화면에 보이는 글자**를 찾습니다.
  스크롤 상자 안이면 그 상자를 스크롤해 결과를 가운데로 가져옵니다.
- 하이라이트는 **본문을 건드리지 않습니다.** 찾기 표시를 본문에 심는 대신 브라우저에 색만 얹으라고
  요청하는 방식이라, 그어 둔 하이라이트·메모의 위치가 검색 때문에 밀리지 않습니다.

### 2. 변환 — 원어 마크다운 다듬기

![변환 화면 — 섹션 트리에서 헤더 레벨 조정](docs/images/02-convert.png)

상단 **1 · 변환** 탭입니다. 왼쪽이 편집, 오른쪽이 결과입니다.

- **레이아웃 자동 수정** — 맨 위 버튼입니다. PDF 추출이 어그러뜨린 곳(제목이 `## 2` + `## Background`
  두 줄로 쪼개짐, 수식이 `x t`처럼 풀어헤쳐짐, 문단·목록·표가 끊김)을 AI가 문서 전체에서 찾아 고칩니다.
  버튼을 누르면 뜨는 창에 **추가 지시**를 적어 넣을 수 있고(비워 둬도 됩니다), `적용`을 누르면
  문서를 구간으로 나눠 차례로 손봅니다. 고친 결과로 **섹션 트리와 일괄 레벨 조정도 다시 만들어지고**,
  지금 정해 둔 레벨·번역 여부·변환 설정은 그대로 이어받습니다.
  글의 내용(단어)은 바꾸지 않습니다 — 구간마다 원문이 보존됐는지 검사해 어긋나면 그 구간은 원문을
  그대로 두고, 마음에 안 들면 같은 창의 `직전 상태로 되돌리기`로 통째로 돌아갈 수 있습니다.
- **섹션 트리** — 감지된 헤더가 순서대로 나옵니다. 왼쪽 드롭다운에서 `제목 1~6`을 골라 레벨을
  바꾸고, `본문으로`(헤더를 풀어 일반 문단으로), `위에 합침`, `통째 삭제`, `기울임`도 고를 수 있습니다.
  `run-in` 배지는 "3.1.2 제목. 본문…" 처럼 본문에 붙어 있던 소제목을 뜻하고, `제목` 배지는 문서 제목입니다.
- **수식** — 추출기(docling)는 수식 자리를 찾아내고도 내용은 비워 둡니다. 그대로 두면 마크다운에
  보이지 않는 주석만 남아 수식이 통째로 사라진 것처럼 보입니다. 그래서 변환할 때 **수식 영역을
  PDF에서 그림으로 잘라내고**, LLM 키가 있으면 그 그림을 읽어 `$$…$$` LaTeX로 바꿔 넣습니다
  (식 번호도 `\tag{1}`로 따라옵니다). 읽기에 실패한 수식은 잘라낸 그림 그대로 남으므로,
  어느 쪽이든 원문에서 사라지지는 않습니다.
- **저자 정리** — 2단 조판 PDF는 저자·이메일·소속이 한 줄에 뭉쳐 나오는데, 변환할 때 저자별로
  분리해 정돈합니다(LLM 키가 있으면 LLM 라벨 + 코드 재조립, 없으면 규칙 기반). 위 화면의
  저자 8명이 그 결과입니다.
- **일괄 레벨 조정** — `3.2.1` 같은 번호 체계를 깊이별로 묶어 한 번에 레벨을 맞춥니다.
- **변환 설정** — 인용 표기(번호 / 저자·연도 / 단축명 조합), 참고문헌 링크, 이미지 처리 등.
- 오른쪽 위 **마크다운 편집** 토글을 켜면 결과 마크다운을 직접 손볼 수 있습니다.
- **그림을 누르면 전체화면으로 확대**됩니다 — 본문 폭에 맞춰 줄어든 도표는 축·범례 글씨가 안
  읽히기 때문입니다. 휠·트랙패드 핀치·`+`/`-`로 배율을 바꾸고(커서 아래 지점이 제자리에 있습니다),
  확대한 채 드래그로 옮기고, 더블클릭이나 `0`으로 맞춤 복귀, `Esc`·배경 클릭으로 닫습니다.
  뷰어 탭의 원문·번역 그림에도 똑같이 걸립니다.
- 고친 내용은 **자동 저장**되고 프리뷰에 바로 반영됩니다. 따로 "저장" 버튼이 없습니다.

### 3. PDF와 나란히 대조

![마크다운 + PDF 나란히 보기](docs/images/03-pdf.png)

**마크다운 + PDF** 를 누르면 오른쪽에 원본 PDF가 함께 뜹니다. 왼쪽 섹션 트리에서 제목을 클릭하면
그 섹션이 있는 **PDF 페이지로 이동**하므로, 추출이 빠뜨린 곳이 없는지 눈으로 대조할 수 있습니다.
`PDF`만 누르면 PDF 전체 화면입니다.

### 4. 번역 — 무엇을, 어떤 말투로

![번역 화면 — 번역할 섹션 선택과 용어집 편집 표](docs/images/04-translate.png)

상단 **2 · 번역** 탭입니다.

- **번역할 섹션** — 체크한 섹션만 번역합니다(비용·시간 절약). 체크를 푼 섹션은 영어 원문 그대로
  남습니다. 참고문헌은 기본적으로 빼는 쪽이 자연스럽습니다.
- **번역 방식** — 문체(해라체 / 합니다체 / 해요체), 헤더를 영어로 둘지 등을 고릅니다.
- **용어집** — Abstract·Introduction 본문과 섹션 제목에서 핵심 용어를 자동으로 뽑아 둡니다.
  번역 전에 한국어 표기와 처리 방식을 표에서 고칠 수 있습니다 — `번역 (의미로)` / `음역 (소리로)` /
  `원문 유지` / `첫 등장 시 원어 병기`. 위 화면은 실제로 뽑힌 결과입니다(`self-attention → 셀프 어텐션`,
  `hidden state → 은닉 상태`). **"이 용어집으로 번역 실행"** 을 누르면 문서 전체가 이 표기로 통일됩니다.

### 5. 뷰어 — 원문과 번역을 나란히

![뷰어 화면 — 영어 원문과 한국어 번역 나란히 보기](docs/images/05-viewer.png)

상단 **3 · 뷰어** 탭입니다. 왼쪽 목차로 이동하고, 원문과 번역을 나란히 놓고 검수합니다
(스크롤이 비율로 동기화됩니다). `첫 등장 시 원어 병기`로 지정한 용어가 "시퀀스 변환(sequence
transduction)"처럼 처리된 걸 여기서 확인할 수 있습니다. **원문 / 번역 / PDF** 버튼으로 보고 싶은
것만 켜고, 오른쪽 위에서 영어·한국어 zip을 바로 내려받습니다.

문장 위에 마우스를 올리면 **그 문장과 짝이 되는 반대쪽 문장이 함께 표시**됩니다 — 어느 문장이
어느 문장인지 눈으로 따라가기 위한 것입니다. 문장 수가 같으면 순서대로 1:1로 잇고, 번역이
한 문장을 둘로 나눴다면 길이비로 1:2·2:1까지 맞춥니다. 짝을 못 지은 문장은 파랑 대신 회색으로
표시해 "여기는 대응을 못 찾았다"는 걸 숨기지 않습니다.

표시를 남기는 길은 둘입니다.

- **드래그** — 끌어 둔 **그 자리**에 하이라이트가 그어집니다. 색을 고르는 막대가 떠서 색을
  고르거나 `메모 달기`로 메모를 붙입니다. 용어 하나, 수식 한 조각만 짚고 싶을 때 씁니다.
- **더블클릭** — 호버로 짝지어 보고 있던 **그 문장 통째로**, **원문과 번역 양쪽에 같은 색으로**
  표시되고 메모 칸이 바로 열립니다. 색은 마지막에 쓴 색을 이어 씁니다.

하이라이트를 다시 누르면 원문·번역 두 문장이 함께 뜨는 카드에서 색을 바꾸거나 메모를 고치거나
지울 수 있고, 툴바의 메모 아이콘으로 전체 목록을 열어 그 자리로 이동할 수 있습니다(목록 서랍은
챗봇 서랍과 마찬가지로 본문을 덮지 않고 오른쪽을 차지하며, 둘은 번갈아 열립니다). 표시한 내용은
작업 폴더의 `annotations.json`에 저장돼 다음에 열어도 그대로 있고, **메모 md** 버튼으로
원문·번역 인용구와 메모를 마크다운 한 장으로 뽑을 수 있습니다.

재조립·재번역으로 본문이 밀려도 하이라이트는 문구로 제자리를 다시 찾습니다. 정말 못 찾은 것은
지우지 않고 목록에 `위치 못 찾음`으로 남습니다.

### 6. 논문에 질문하기 — 답의 근거를 그 문단으로 (LLM 키 필요)

읽다가 생긴 질문은 뷰어 툴바의 **말풍선 아이콘**으로 엽니다. PDF 패널처럼 **오른쪽 한 칸을
차지하고**(본문을 덮지 않고 그만큼 좁아집니다), 이 논문 한 편에 대해서만 답합니다. 왼쪽
모서리를 드래그해 너비를 조절할 수 있고, 그 너비는 기억됩니다.

- **답에 붙은 인용 번호를 누르면 근거가 된 문단으로 이동합니다.** 답을 믿으라고 하는 대신 어디서
  나왔는지 보여주려는 것입니다 — 뷰어가 그 문단으로 스크롤하며 깜빡입니다. 원문과 번역이 이미
  나란히 있는 곳이라, 서랍 안에 문단을 다시 그리지는 않습니다(어디로 가는지는 칩에 마우스를
  올리면 미리 보입니다). 답 아래 `검색된 문단 N개`를 누르면 무엇을 뒤졌는지 목록으로 봅니다.
- **모델은 서랍 헤더에서 고릅니다.** 짧은 문답이라 논문 한 편을 통으로 번역할 때와 다른 등급을
  쓰고 싶을 수 있어, **챗봇 모델은 따로 저장되고 번역 설정은 건드리지 않습니다.** 목록에는 세
  제공사의 모델이 단가와 함께 나오고, 키가 없는 제공사는 `(키 없음)`으로 표시만 됩니다.
- **한국어로 물어도 영어 원문에서 찾습니다.** 검색은 임베딩 없이 BM25(순수 파이썬)로 돌고, 영문은
  단어 단위, 한글은 문자 바이그램으로 쪼갭니다. 어휘가 어긋나면 LLM이 뽑아 준 동의어 키워드로
  질문을 넓혀 다시 찾습니다. 답은 **질문한 언어로** 돌아옵니다.
- **내가 그어 둔 하이라이트·메모도 함께 검색합니다** — "내가 표시해 둔 데서 뭐라고 했지?"가 논문
  본문 질문과 한 창에서 답됩니다. 다만 메모는 논문이 아니라 **내가 쓴 글**이므로 답에서 구분해서
  말하고 인용 표기도 따로 씁니다. 헤드의 **메모 포함** 토글로 끕니다.
- **모르면 모른다고 합니다.** 검색된 문단에 없는 내용은 지어내지 말라고 지시했고, 프롬프트에 넣지
  않은 문단을 가리키는 인용은 화면에 그리기 전에 지웁니다.
- 대화는 작업 폴더의 `chat.json`에 남아 다음에 열어도 이어지고, **턴마다 실제 비용이 표시**됩니다
  (질문 하나에 LLM 호출 2회 — 검색어 확장 1회 + 답변 1회). 헤드의 `지우기`로 기록을 지웁니다.
- LLM 키가 없으면 서랍이 그 이유를 알려 줍니다 — 이 기능만 안 되고 나머지는 그대로 돌아갑니다.

## 내보내기 — 어떤 형식으로, 어디에 넣나

화면 오른쪽 위의 **내보내기 형식** 드롭다운(범용 / Notion / Obsidian)을 고르고
**"영어 다운로드 (zip)"** 또는 **"한국어 다운로드 (zip)"** 를 누릅니다. 홈에서는 여러 논문을
한 zip으로 묶어 받을 수도 있습니다. 고른 형식은 기억됩니다.

zip을 풀면 이렇게 생겼습니다:

```
<논문이름>-en/
├── <논문이름>.en.md      ← 선택한 형식으로 변환된 마크다운
└── images/               ← 본문에서 실제로 참조된 그림·표만
```

원본 `en.md` / `ko.md`는 항상 범용 형태로 보관되고 **다운로드할 때만 변환**되므로, 형식을 바꿔
다시 받아도 손실이 없습니다. (CLI에서 `--flavor`를 주면 예외로 작업 폴더의 파일 자체가 그 형식으로
저장됩니다.)

### 범용 (universal) — 기본값

표준 마크다운 그대로입니다. 이미지는 `![](images/fig-01.png)`, 인용은 `[1](#ref-1)` 문서 내
앵커 링크, 각주는 `<sup>` HTML입니다.

- **쓰는 곳** — GitHub·GitLab 저장소에 올려 읽기, VS Code·Typora·Zettlr 같은 마크다운 에디터,
  Pandoc·Quarto로 PDF/DOCX/HTML 변환, MkDocs·Hugo·Jekyll 같은 정적 사이트, LLM에 논문 전문을
  통째로 붙여넣기.
- **넣는 법** — zip을 풀고 `.md`를 열면 끝입니다. 다만 **`.md`와 `images/`가 같은 폴더에 함께
  있어야** 그림이 보입니다. 옮길 때는 폴더째 옮기세요.
- 인용 링크(`#ref-N`)는 GitHub와 VS Code 프리뷰에서 동작합니다 — 본문의 `[1]`을 누르면 참고문헌으로 갑니다.
- 어디에 넣을지 아직 모르겠으면 범용을 받으세요. 나머지 두 형식은 여기서 파생됩니다.

### Notion

Notion 임포터가 처리하지 못하는 문법을 미리 바꿉니다 — 문서 내 앵커 링크를 없애고(Notion은 이걸
`about:blank#...`로 깨뜨립니다), 인용은 **DOI/arXiv URL이 있으면 그 링크로**, 없으면 텍스트만
남깁니다. 각주 번호는 유니코드 위첨자(¹ ² ³)로, 이미지 alt는 비웁니다(Notion이 alt를 캡션으로
띄우는데 캡션 블록이 따로 있어서 중복되기 때문).

- **넣는 법** — Notion 왼쪽 아래 **Import → Markdown & CSV**에서 **zip 파일을 풀지 말고 그대로**
  선택합니다. 그림이 함께 올라갑니다.
- **알려진 자국** — 임포트 후 `images`라는 빈 페이지가 하나 생깁니다. 지우면 됩니다.
  (이 구조가 본문 임포트가 가장 안정적이어서 그대로 뒀습니다.)

### Obsidian

Obsidian 문법으로 바꿉니다 — 이미지는 위키 임베드 `![[<논문폴더>/images/fig-01.png]]`,
인용은 블록 링크 `[1](#^ref-1)`가 되고 참고문헌 줄 끝에 블록 id `^ref-1`이 붙습니다.
그래서 **본문 인용을 누르면 해당 참고문헌으로 점프하고, `Cmd/Ctrl + ←`로 읽던 자리에 돌아옵니다.**
각주도 같은 방식입니다.

- **넣는 법** — zip을 풀어서 `<논문이름>-en` **폴더째** vault 안에 복사합니다.
- **주의** — 임베드 경로에 폴더 이름이 박혀 있으므로 **폴더 이름을 바꾸면 그림이 깨집니다.**
  폴더명에 논문 이름이 들어가는 건 여러 논문을 한 vault에 넣어도 이미지가 충돌하지 않게 하려는 것입니다.

## 프로젝트 — 논문을 묶어 관리하기

논문이 스무 편을 넘어가면 목록이 한 덩어리가 됩니다. **프로젝트**는 그 덩어리를 갈라 두는
칸입니다 — 학위 서베이, 이번 학기 수업, 진행 중인 연구를 각각 프로젝트로 두면 목록에서 서로
섞이지 않습니다. 홈 왼쪽 **프로젝트** 패널에서 만들고, 이름을 고치고, 지웁니다.

프로젝트마다 **폴더 하나만** 고르면 그 안에 자리가 자동으로 잡힙니다. 영어·한국어·PDF가 갈
폴더를 따로 지정할 필요가 없습니다.

```
<프로젝트 폴더>/2017_Attention_Vaswani.md          ← 영어 마크다운은 루트
<프로젝트 폴더>/images/2017_Attention_Vaswani/     ← 그림
<프로젝트 폴더>/ko/2017_Attention_Vaswani.md       ← 번역본
<프로젝트 폴더>/pdf/2017_Attention_Vaswani.pdf     ← 원본 PDF
<프로젝트 폴더>/references.bib                     ← BibTeX 항목이 계속 덧붙습니다
```

- 오른쪽 **변환한 논문** 목록은 선택 상자로 **한 프로젝트만 걸러 보거나**, 프로젝트별 구역으로
  묶어 전체를 훑을 수 있습니다.
- 카드의 **프로젝트 칩**을 눌러 다른 프로젝트로 옮기면 **저장 위치의 사본도 함께 옮겨집니다** —
  마크다운·이미지·PDF·`references.bib` 항목이 새 폴더에 다시 놓이고 옛 폴더에서는 정리됩니다.
  옛 폴더에 고아가 남지 않습니다. (자동 저장을 꺼 두었더라도 옮기기는 옮깁니다 — 이미 내보낸
  사본이 엉뚱한 폴더에 남아 있는 편이 더 나쁘기 때문입니다.)
- 목록에서 고른 프로젝트가 **새로 올리는 논문의 소속**이 됩니다. 드롭존이 어느 프로젝트로
  들어갈지 이름으로 알려 줍니다.
- 폴더를 정하지 않은 프로젝트와 **미분류** 논문은 아래
  [저장 위치](#저장-위치--변환한-논문을-한-폴더에-쌓기)의 공통 폴더로 갑니다.
- 프로젝트를 지워도 **폴더와 파일은 그대로**입니다. 그 안에 있던 논문은 미분류가 됩니다.

### 프로젝트마다 다르게 설정하기

프로젝트 행의 **이 프로젝트만 다르게**를 펼치면 그 묶음에만 적용할 설정을 정할 수 있습니다.

| 항목 | 예 |
|---|---|
| 이름 규칙 | `{year}_{author}_{title}` |
| 내보내기 형식 | 범용 · Notion · Obsidian |
| references.bib 쌓기 | 켜기 / 끄기 |
| 변환·번역 후 자동 저장 | 켜기 / 끄기 |

- 정하지 않은 항목은 **전역 설정을 그대로 따릅니다**(복사본이 아니라 덮어쓰기입니다). 그래서
  전역 설정을 고치면 따로 정하지 않은 프로젝트들은 저절로 따라옵니다 — 설정을 두 군데서
  관리하지 않아도 됩니다.
- 끈 것과 안 정한 것은 다릅니다. 프로젝트에서 BibTeX를 **끄면** 전역이 켜져 있어도 꺼진 채입니다.
- CLI로도 됩니다: `md4paper project set NIRVANA export_target obsidian` ·
  해제는 `md4paper project set NIRVANA export_target --unset` · 조회는 KEY 없이.

번역 문체나 추출 설정 같은 건 전역에만 둡니다 — 프로젝트 설정 화면이 전역 설정을 통째로
복제하면 지금 보는 값이 어디서 온 건지 헷갈리기 때문입니다.

### BibTeX — references.bib가 쌓입니다

논문 하나에 항목 하나가 저장 위치의 `references.bib`에 **덧붙습니다.** 그대로 복사해 원고의
`.bib`에 붙여도 되고, 파일째 Overleaf에 올리거나 Zotero로 가져가도 됩니다.

인용 키는 논문 기준명이라 마크다운·PDF 파일명과 **같은 이름**입니다 — 노트에 적어 둔
`2017_Attention_Vaswani`와 `\cite{2017_Attention_Vaswani}`가 어긋나지 않습니다. 기준명에
한글처럼 ASCII가 아닌 글자가 있으면 그 부분을 빼고 짧은 해시를 붙입니다(`2024-d7606b`) —
고전 `bibtex`가 UTF-8 키에서 깨지기 때문이고, 그냥 빼기만 하면 서로 다른 논문이 같은 키가 됩니다.

```bibtex
@inproceedings{2017_Attention_Vaswani,
  author    = {Vaswani, Ashish and Shazeer, Noam},
  booktitle = {Advances in Neural Information Processing Systems},
  title     = {{Attention Is All You Need}},
  year      = {2017}
}
```

- 같은 논문을 다시 내보내면 새 항목이 생기는 게 아니라 **그 항목이 갱신됩니다.** 파일을 통째로
  다시 쓰지는 않으므로 손으로 넣은 항목·주석은 그대로 보존됩니다.
- **문자열을 직접 만들지 않습니다.** 논문 제목에는 `&`, `%`, `_`, 악센트 문자가 흔히 들어가고,
  이스케이프를 손으로 짜면 언젠가 `\cite`가 아니라 **LaTeX 컴파일이** 깨집니다 — 그 사실은 보통
  마감 전날 알게 됩니다. 그래서 이스케이프와 직렬화는
  [bibtexparser](https://github.com/sciunto-org/python-bibtexparser)에 맡기고, 만든 항목을
  **되읽어** 키·종류·필드가 그대로 돌아오는지 확인한 뒤에 파일에 씁니다.
- 쓴 다음에도 **파일 전체를 다시 파싱해** 항목 수가 줄지 않았는지 봅니다. 줄었으면 **쓰기 전으로
  되돌립니다** — 몇 달 쌓아 둔 참고문헌 파일을 우리가 깨뜨리는 일은 없어야 합니다.
- 서지 정보(제목)가 없는 논문은 항목을 만들 수 없으니 조용히 건너뜁니다. 기능 자체는 **저장 위치**
  패널의 **BibTeX(references.bib)도 함께 쌓기** 스위치로 끕니다.

#### 정확한 항목은 논문 API에서 받아옵니다

PDF 1페이지에 없는 것은 우리도 만들어 낼 수 없습니다 — 학회 이름이 각주에 `CHI '24`처럼만 적혀
있거나 아예 없는 논문이 많고, DOI·페이지·출판사는 애초에 1페이지에 없습니다. 그래서 **항목을
조립하는 대신 출판 기록을 받아옵니다.**

**논문을 올리면 변환 끝에 저절로 한 번 돕니다** — 그래서 처음 쌓이는 `references.bib`부터
정확합니다. 나중에 손볼 필요가 없도록 기본으로 켜 뒀고, 네트워크가 느리면 저장 위치 패널의
*변환이 끝나면 서지를 온라인에서 보강* 스위치로 끕니다(프로젝트별로도 정할 수 있습니다).

이미 변환해 둔 논문은 저장 위치 패널의 **서지 정보 보강** 버튼(또는 `md4paper enrich`)으로
**지금 고른 프로젝트의** 논문에 대해 같은 일을 합니다:

1. **Ai2의 Semantic Scholar**가 제목으로 그 논문을 찾습니다. 추출이 `Effect`를 `Efect`로
   흘렸어도 찾아냅니다.
2. 찾은 **DOI로 Crossref**에서 출판사가 등록한 항목을 받습니다.

```bibtex
@inproceedings{2024_HaLLMarkEffect_Hoque,
  author    = {Hoque, Md Naimul and Mashiat, Tasfia and Ghai, Bhavya and ...},
  booktitle = {Proceedings of the CHI Conference on Human Factors in Computing Systems},
  doi       = {10.1145/3613904.3641895},
  pages     = {1--15},
  publisher = {ACM},
  series    = {CHI '24},
  title     = {{The HaLLMark Effect: Supporting Provenance and Transparent Use of ...}},
  year      = {2024}
}
```

- **연도·학회·제목은 출판사 기록이 이깁니다.** PDF에서 2008년으로 읽었던 Flower & Hayes 논문이
  실제로는 1981년 *College Composition & Communication* 32(4) 365–387입니다. `paper_meta.json`
  (목록·검색·파일명이 쓰는 값)은 건드리지 않고, `.bib` 항목에만 적용합니다.
- **같은 논문일 때만 받아들입니다.** 제목 유사도 하나로는 부족합니다 — 단어 하나가 다른 남의 논문이
  0.96으로 통과하는 걸 실측했습니다. 그래서 **저자 성과 연도로 교차 확인**하고, 어느 API에서도
  확신이 안 서면 아무것도 바꾸지 않습니다(틀린 서지가 빈 서지보다 나쁩니다).
- **전송되는 건 논문 제목뿐입니다.** 본문은 나가지 않습니다. 받은 기록은 논문 폴더의
  `bib_source.json`에 저장돼, 다시 내보낼 때는 네트워크를 쓰지 않습니다.
- 어느 API에도 없는 논문(오래된 스캔본 등)은 PDF에서 읽은 값 그대로 남습니다.
- `md4paper bib`는 **네트워크를 쓰지 않습니다** — 받아 둔 기록으로 `.bib`만 다시 씁니다.
- **범위는 지금 고른 프로젝트**입니다(홈의 프로젝트 필터와 같습니다). 한 번에 한 묶음을 손보는 게
  보통인데 전체를 훑으면 예전 프로젝트까지 API를 두드리게 되기 때문입니다. 전체를 돌리려면
  `md4paper enrich --all`, 다른 묶음은 `--project <이름>`.
- **진행률이 보이고 언제든 멈출 수 있습니다.** 논문 한 편에 몇 초에서 몇십 초가 걸립니다(참고문헌이
  100건이면 2분쯤). **중지**를 누르면 지금 논문까지만 마치고 멈추며, 그때까지 보강한 내용은
  이미 저장돼 있습니다. CLI는 진행 막대 + Ctrl+C.

## 저장 위치 — 변환한 논문을 한 폴더에 쌓기

매번 zip을 받아 푸는 대신, **변환·번역이 끝나면 정해 둔 폴더에 마크다운이 자동으로 쌓이게**
할 수 있습니다. 홈 왼쪽 **저장 위치**를 펼치고 **폴더 아이콘**을 누르면 OS 기본 폴더 선택
대화상자가 열립니다(경로를 직접 붙여넣어도 됩니다).

여기서 정하는 폴더는 **공통 자리**입니다 — 폴더를 따로 정해 둔 프로젝트의 논문은 그 프로젝트
폴더로 가고, 나머지(미분류 논문과 폴더를 정하지 않은 프로젝트)가 이 공통 폴더로 옵니다.

**영어 마크다운·한국어 마크다운·원본 PDF를 서로 다른 폴더로 보낼 수 있습니다** — 예를 들어
Obsidian 볼트의 `Papers/EN`, `Papers/KO`, `Papers/PDF`. 필요한 것만 정해도 되고, 영어와
한국어를 같은 폴더로 두면 파일 이름 뒤에 `.en` / `.ko`가 붙어 구분됩니다.

```
Papers/EN/2017_Attention_Vaswani.md          ← 논문 하나에 파일 하나
Papers/EN/images/2017_Attention_Vaswani/     ← 그림은 논문별 폴더로 격리
Papers/KO/2017_Attention_Vaswani.md          ← 번역본은 다른 폴더에 같은 이름으로
Papers/PDF/2017_Attention_Vaswani.pdf        ← 원본 PDF도 같은 이름 → md에서 바로 찾음
```

- **폴더 하나로 정리** 버튼은 프로젝트와 같은 배치를 공통 자리에도 적용합니다 — 루트 폴더 하나만
  고르면 영어 마크다운은 그 루트에, 번역본은 `ko/`, 원본 PDF는 `pdf/`로 갈라 넣습니다.
  세 폴더를 각각 정하는 게 번거로울 때 쓰세요.
- 형식은 **내보내기 형식**(범용 / Notion / Obsidian) 설정을 그대로 따릅니다.
- 같은 논문을 다시 내보내면 **덮어씁니다** — 버전이 아니라 논문이 쌓입니다.
- 자동 저장 시점은 ① 변환 완료 ② 번역 완료 ③ 구조·설정을 고쳐 재조립할 때입니다.
  자동 저장을 끄면 논문 화면의 **폴더로 저장** 버튼이나 홈의 **이미 변환한 논문도 지금 내보내기**로
  직접 내보냅니다(목록에서 여러 편을 체크해 한 번에 보낼 수도 있습니다).

### 파일 이름 규칙

논문 폴더·작업 폴더의 PDF·저장 위치의 md/PDF가 **모두 같은 기준명**을 씁니다. 기준명은
서지 정보(LLM 추출)에서 **이름 규칙**으로 만드는데, 기본은 `{year}_{title}_{author}`
(예: `2017_AttentionIsAllYouNeed_Vaswani`)이고 **저장 위치** 패널에서 바꿀 수 있습니다.

- 조각: `{year}` 연도 · `{title}` 제목 약칭(CamelCase) · `{author}` 1저자 성 · `{venue}` 학회.
  없는 조각(연도 미상 등)은 자동으로 빠집니다.
- 업로드한 파일 이름이 `2412.01234v2.pdf`여도 변환이 끝나면 폴더와 PDF가 규칙 이름으로 바뀝니다.
- **기존 논문·PDF 이름 정리** 버튼을 누르면 이미 변환해 둔 논문 전체가 현재 규칙으로 정리됩니다 —
  폴더·PDF·저장 위치 사본을 리네임하고, 옛 이름으로 내보냈던 사본은 청소합니다.
  (서지 정보가 없는 논문은 이름을 만들 수 없어 건너뜁니다.)

터미널에서도 같은 설정을 만집니다:

```bash
uv run md4paper project                                   # 프로젝트 목록 · 지금 고른 프로젝트
uv run md4paper project add "튜터 챗봇 서베이" --dir ~/Vault/Tutor
uv run md4paper project use "튜터 챗봇 서베이"            # 새 논문이 들어갈 프로젝트
uv run md4paper project assign "튜터 챗봇" output/2017_.../2017_....md4
uv run md4paper library                                   # 현재 저장 위치 확인
uv run md4paper library --en ~/Papers/EN --ko ~/Papers/KO --pdf ~/Papers/PDF
uv run md4paper library --root ~/Papers                   # 공통 저장 위치를 폴더 하나로
uv run md4paper library --export                          # 이미 변환한 논문 전부 내보내기
uv run md4paper library --off all                         # 해제
uv run md4paper bib --all                                 # references.bib 다시 채우기 (논문 API 조회)
uv run md4paper naming                                    # 이름 규칙 확인
uv run md4paper naming "{author}{year}_{title}"           # 규칙 변경
uv run md4paper naming --apply                            # 기존 논문·PDF 이름 정리
```

### 서지 정보 보강 (선택)

연도나 학회가 비어 있는 논문은 **공개 서지 API**에서 찾아 채울 수 있습니다. 저장 위치 패널의
**서지 정보 보강** 버튼 또는 `md4paper enrich --all`입니다.

- 1차 [OpenAlex](https://openalex.org), arXiv만 잡히면 [Crossref](https://www.crossref.org)로 출판 학회를 보강합니다. 둘 다 무료·키 불필요.
- **논문 제목만 전송**합니다(본문은 나가지 않습니다). PDF에서 읽은 값은 **덮어쓰지 않고**, 비어 있는 칸만 채웁니다.
- 조회 결과의 제목이 우리 제목과 충분히 일치할 때만 채택합니다. Crossref는 유사도와 무관하게 1등을
  돌려주기 때문에(실측: 2026년 논문 질의에 2010년 책 반환) 이 검증이 없으면 엉뚱한 연도가 조용히 들어옵니다.
- `[enrich].mailto`에 이메일을 넣으면 API의 polite pool을 씁니다: `md4paper enrich --all --mailto you@example.com`

## LLM API 키 설정 (번역·인용 기능에만 필요)

웹 UI 홈의 **AI 설정** 패널에 키를 붙여넣고 **연결 테스트**를 누르는 게 가장 간단합니다.
터미널을 쓰려면:

```bash
uv run md4paper keys set openai      # ~/.config/md4paper/config.toml 에 저장 (권한 0600)
uv run md4paper keys list            # 설정 여부 확인 (값은 마스킹)
```

또는 환경 변수 — 공용 컴퓨터에서 권장:

| 프로바이더 | 환경 변수 | 기본 모델 |
|---|---|---|
| OpenAI | `OPENAI_API_KEY` | `gpt-6-luna` |
| Anthropic | `ANTHROPIC_API_KEY` | `claude-haiku-4-5` |
| Google Gemini | `GEMINI_API_KEY` | `gemini-3.5-flash-lite` |

기본 모델은 각 사 최신 세대에서 가장 저렴한 등급입니다. 계정에 해당 모델이 없으면 UI에서 다른
프로바이더를 고르거나, CLI에 `--model <모델명>`을 붙이세요(구형 모델도 그대로 쓸 수 있습니다).

## 비용 — 논문 한 편에 얼마나 드나

**PDF → 마크다운 추출만 하면 $0입니다.** 추출은 전부 로컬에서 돌아갑니다.
돈이 드는 건 참고문헌 파싱 · 용어집 생성 · 번역, 그리고 뷰어 챗봇의 질문뿐입니다.
수식이 있는 논문은 수식 읽기가 더해지는데, 수식 하나에 약 $0.0005입니다 — 수식 25개짜리
논문(TextGrad)이 **$0.012**로 실측됐습니다. 수식이 없는 논문에서는 아예 호출하지 않습니다.

**실측치**: 이 README의 스크린샷에 쓴 *Attention Is All You Need*(15쪽, 본문 4.9만 자)를 당시 기본 모델
`gpt-5.6-luna`로 **용어집 자동 생성 + 전문 번역**했더니 도구가 출력한 실제 비용은 **$0.031**
(청크 15개, 약 45원)이었습니다. 비용은 본문 길이에 거의 비례하므로:

| 논문 | `gpt-5.6-luna` (당시 기본) |
|---|---|
| 짧은 논문 (본문 약 5만 자) — **실측** | **$0.031** |
| 일반적인 학회 논문 (본문 약 7만 자) | 약 $0.04 |
| 부록까지 긴 논문 (본문 약 24만 자) | 약 $0.14 |

여기에 참고문헌 파싱(인용 링크)을 함께 돌리면 논문당 $0.01-0.02 정도가 더 붙습니다.
즉 **보통 논문 한 편에 70-90원, 아주 긴 논문도 250원 안팎**입니다.

현재 기본인 `gpt-6-luna`는 $0.1/$0.5(1M 토큰당)로 `gpt-5.6-luna`보다 입력은 절반, 출력은 약 42%
단가라, 같은 논문이 위 금액의 **절반 안팎**(짧은 논문 약 $0.013-0.016)으로 나올 것으로 예상됩니다 —
아직 `gpt-6-luna`로 다시 실측하지는 않았습니다.

**뷰어 챗봇**은 질문 하나가 논문 전체가 아니라 검색된 문단 8개와 최근 대화 몇 턴만 실어 보내므로
번역보다 훨씬 작습니다 — 정확한 금액은 답변마다 그 자리에 표시되니 처음 몇 번은 그걸 보세요.

> 2026-07-30 OpenAI 인하로 `gpt-5.6-luna`가 $1/$6 → $0.2/$1.2(1M 토큰당)가 되면서 위 금액은
> 종전의 5분의 1이 됐습니다. 실측 행은 같은 실측 토큰 사용량에 새 단가를 적용한 값입니다.
> 이 인하로 기본 모델이 세 프로바이더를 통틀어 가장 저렴해졌습니다 — 예전에는 Gemini로 바꾸면
> 훨씬 쌌지만, 지금은 `gemini-3.5-flash-lite`($0.3/$2.5)가 오히려 비쌉니다. 프로바이더는
> 이제 비용보다 번역 품질 취향으로 고르세요.

돈이 새지 않게 하는 장치:

- **실행이 끝나면 실제 비용을 출력합니다** — `비용 ≈ $0.0306 → paper.ko.md`
- **번역 캐시** — 구조를 고쳐 다시 돌려도 내용이 그대로인 청크는 다시 번역하지 않습니다.
- **번역 범위 선택** — 필요한 섹션만 골라 번역할 수 있습니다.
- **챗봇은 턴마다 실비용을 답변에 붙입니다** — 대화가 길어져도 얼마 썼는지 그때그때 보입니다.

> 실측치는 2026-07 기준 [base.py](src/md4paper/llm/base.py)의 가격표로 계산됩니다. 각 사 가격
> 정책이 바뀌면 달라지니, 처음에는 짧은 논문으로 한 번 돌려 출력되는 실비용을 확인해 보세요.

## 파일이 저장되는 곳

| 항목 | 경로 |
|---|---|
| 작업 폴더(기본) | 저장소에서 실행: `<저장소>/output/` · `uvx` 실행: `~/md4paper/output/` |
| 논문별 결과 | `<작업폴더>/<이름>/<이름>.md4/` (추출 원문·구조·번역·로그) |
| 최종 마크다운 | `<이름>.md4/out/paper.en.md`, `paper.ko.md`, `out/images/` |
| 저장 위치(선택) | 직접 고른 폴더에 `<논문이름>.md` + `images/<논문이름>/` + `<논문이름>.pdf` — 영어·한국어·PDF 따로 |
| 프로젝트 목록 | `~/.config/md4paper/projects.json` (프로젝트 이름·폴더, 지금 고른 프로젝트) |
| 논문의 소속 | `<이름>.md4/status.json`의 `project` 필드 (프로젝트 id, 비어 있으면 미분류) |
| 설정·API 키 | `~/.config/md4paper/config.toml` (Windows: `C:\Users\<사용자>\.config\md4paper\config.toml`) |
| 헤더 처리 기억 | `~/.config/md4paper/heading_prefs.json` |
| Docling 모델 캐시 | `~/.cache/huggingface` (Windows: `C:\Users\<사용자>\.cache\huggingface`) |
| 앱 런처(선택) | macOS `~/Applications/md4paper.app` · Windows 시작 메뉴 · Linux `~/.local/share/applications` |
| 앱 실행 로그 | macOS `~/Library/Logs/md4paper.log` (아이콘으로 띄웠을 때) |

작업 폴더 변경: 홈의 **저장 위치 → 작업 폴더 → 변경**, `uv run md4paper workspace <경로>`,
또는 `md4paper ui --upload-dir <경로>`.

기본값은 위 표처럼 **실행 방식에 따라 다르지만**, UI를 처음 켤 때 그때의 값이 설정 파일에
기록됩니다. 그래서 클론으로 쓰다가 아이콘(한 줄 설치본)으로 갈아타도 **같은 폴더를 계속 봅니다**
— 변환해 둔 논문이 목록에서 사라지지 않습니다. 결과 마크다운을 쌓을 폴더는
[저장 위치](#저장-위치--변환한-논문을-한-폴더에-쌓기)에서 따로 정합니다(작업 폴더와 별개).

## CLI (선택 — 자동화·배치용)

웹 UI로 할 수 있는 일은 대부분 터미널에서도 됩니다. 여러 편을 스크립트로 돌리거나 서버에서
쓸 때 편합니다.

```bash
uv run md4paper doctor                  # 환경 점검
uv run md4paper convert paper.pdf       # PDF → paper.md4/out/paper.en.md
uv run md4paper review paper.md4/       # 섹션 매니페스트를 $EDITOR로 열어 교정 후 재조립
uv run md4paper cite paper.md4/         # 참고문헌 파싱 + 본문 인용 링크 (LLM)
uv run md4paper glossary paper.md4/     # 번역 전 용어집 생성 (LLM)
uv run md4paper translate paper.md4/    # 한국어 번역 → paper.md4/out/paper.ko.md (LLM)
uv run md4paper ui paper.md4/           # 이 작업을 웹 UI로 열기
uv run md4paper workspace               # 작업 폴더 조회 / 변경
uv run md4paper project                 # 프로젝트 목록 / add · use · assign
uv run md4paper library                 # 저장 위치(영어·한국어·PDF 폴더) 조회 / 변경 / --root
uv run md4paper bib --all               # 저장 위치의 references.bib 다시 채우기 (논문 API 조회)
uv run md4paper naming                  # 파일 이름 규칙 조회 / 변경 / --apply 일괄 정리
uv run md4paper enrich --all            # 빈 연도·학회를 공개 서지 API로 보강
uv run md4paper prefs list              # 기억된 헤더 처리 목록
uv run md4paper app                     # 더블클릭용 앱 아이콘 등록 (--remove로 제거)
```

주요 옵션:

- `convert --ocr` — 스캔 PDF용 OCR (born-digital 논문에는 불필요, 느립니다)
- `convert --flavor standard|obsidian|notion` — 내보내기 형식 (위 [내보내기](#내보내기--어떤-형식으로-어디에-넣나) 참조)
- `translate --style 합니다체` — 문체 지정
- `cite --style keep|authoryear|short` — 인용 표기
- `review` — `$EDITOR`(Windows는 미설정 시 메모장)로 매니페스트를 엽니다

`uvx`로 설치했다면 `uv run` 없이 `md4paper convert paper.pdf`처럼 씁니다.

## 문제 해결

**공통**

- `md4paper doctor`를 먼저 실행하세요. 필수 항목이 모두 ✓면 변환은 됩니다.
  LLM 키가 `-`로 표시되는 건 실패가 아니라 "선택 기능 미설정"입니다.
- 변환해 둔 논문이 목록에 안 보임 → 파일이 지워진 게 아니라 **작업 폴더가 다른 곳을 가리키는** 것입니다.
  목록이 비어 있으면 홈에 지금 보고 있는 폴더 경로가 표시되니, **저장 위치 → 작업 폴더**에서 예전
  폴더로 바꾸세요(`md4paper workspace <경로>`도 같습니다).
- 앱 아이콘을 눌렀는데 아무 창도 안 뜸 → 실행 로그(macOS `~/Library/Logs/md4paper.log`)를 보세요.
  대개 `uv sync --extra ui --extra native`를 안 했거나, 저장소를 옮긴 뒤 `md4paper app`을
  다시 실행하지 않은 경우입니다.
- 앱 창에 AI 키가 안 보임 → 아이콘 실행은 셸 환경변수를 물려받지 않습니다. 홈의 **AI 설정**에
  키를 저장하세요.
- 첫 변환이 오래 걸림 → Docling 모델(약 1.1GB)을 내려받는 중입니다. 두 번째부터 빨라집니다.
- 결과가 이상함 → 섹션 트리에서 헤더 레벨을 교정하고, PDF 나란히 보기로 대조하세요.
  스캔 PDF라면 OCR이 필요합니다.

**Windows**

- `uv: 명령을 찾을 수 없음` → PowerShell을 새로 열거나 로그아웃/로그인하세요.
- `git`이 없다면 [git-scm.com](https://git-scm.com/download/win)에서 설치하거나, 클론이 필요 없는
  **방법 B**를 쓰세요.
- 실행 정책 오류(`running scripts is disabled`) → uv 설치 명령의 `-ExecutionPolicy ByPass` 부분을
  빠뜨리지 않았는지 확인하세요.
- 경로가 아주 긴 폴더에서 설치가 실패하면 짧은 경로(예: `C:\dev\md4paper`)로 옮겨 보세요.

**macOS**

- Apple Silicon/Intel 모두 CPU로 동작합니다(GPU 불필요).
- 브라우저가 자동으로 안 열리면 터미널에 찍힌 `http://127.0.0.1:8080`을 직접 여세요.

**Linux**

- `ImportError: libGL.so.1: cannot open shared object file` → OpenCV 런타임 의존성입니다:
  ```bash
  sudo apt install -y libgl1 libglib2.0-0     # Debian/Ubuntu
  ```
- 헤드리스 서버에서는 `--no-show`로 실행하고 SSH 포트 포워딩으로 접속하세요:
  ```bash
  md4paper ui --no-show --port 8080
  ssh -L 8080:127.0.0.1:8080 <사용자>@<서버>   # 로컬에서
  ```
  서버는 127.0.0.1에만 바인딩하므로 **인증 없이 외부에 열지 마세요**(그럴 의도로 만들지 않았습니다).
- 배포판 기본 torch가 CUDA 빌드라 설치 용량이 클 수 있습니다. GPU가 없어도 동작합니다.

## 개발

```bash
uv sync --extra ui
uv run pytest -q          # 테스트 (LLM 호출 없이 fake 프로바이더로 전부 돌아갑니다)
uv run ruff check .       # 린트
```

설계 문서와 마일스톤은 [PLAN.md](PLAN.md)에 있습니다.
`uv sync --extra X`는 다른 extra를 제거하니, 여러 개가 필요하면 한 번에 지정하세요.
